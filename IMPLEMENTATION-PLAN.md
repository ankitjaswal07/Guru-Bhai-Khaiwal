# Implementation plan — written before code changes

Date: 2026-10-26. Inputs: satta20.zip and scheduled-results-manager.zip. Both originals remain untouched; extracted read-only inspection copies are under originals/ (not release files).

## Inspection findings
- Theme: classic PHP WordPress architecture; front-page section dispatcher, reusable header/hero/games/results/contact/blog/FAQ/footer parts, eight custom page templates, native post archives/search/comments. ACF PRO options/repeaters provide almost all editing. No confirmed ACF license. CSS is split into overlapping responsive/component files; JS adds clock, slider, navigation and FAQ interaction. Theme has no result tables of its own and delegates through shortcodes. Retain that separation and familiar page-template paths.
- Plugin version 1.1.0 / PHP 8.1: `srm_events` (id, bilingual names, unique slug, TIME, order, active flag, timestamps) and `srm_results` (id, event_id, date, value, pending/published status, timestamps; UNIQUE event_date). Existing schedules and IDs must survive upgrades.
- Plugin has games/results/monthly/settings/import-export screens, user-game capability assignments, AJAX saves and a public `srm/v1` REST API (current/today/monthly/games/events). Shortcodes cover schedules, current/next, today/yesterday, monthly and individual game history. Existing data schema and aliases are reusable.
- Critical findings: public daily/monthly/current API paths can return pending values; seed code automatically publishes July/August values without provenance; CSV import uses upsert and trusts publication status; no source/verification/reviewer metadata; incomplete date validation on saves; broad admin-action permission check does not distinguish schedule/settings from restricted result operators; delete handler lacks per-game authorization; shared monthly caches risk mixing admin/public data. Uninstall can erase tables and references access class without loading it.
- No build tooling or runtime/test installation supplied. Sandbox has Node/Python but no native PHP/MySQL. Investigate WordPress Playground PHP-WASM/SQLite for executable integration tests; hosting MySQL/PHP validation remains a separate release gate if unavailable.
- All input PHP/CSS/JS and metadata files inventoried; focused review of schema, CRUD, access, API, seeding, shortcode queries, admin actions, templates, ACF defaults and assets. Actual code differs from live content (e.g. source ZIP historical seed period).

## Implementation sequence
1. Create separate `project/` theme and plugin; record input SHA256 and file inventory. Keep plugin directory/main filename `scheduled-results-manager` for in-place WordPress upgrades; use branded downloadable ZIP name.
2. Reuse events/access/database foundations. Add provenance columns/indexes and durable import log table with dbDelta. Never delete or rewrite existing results; legacy records become unverified by default and are excluded from public displays pending review. Seed only the 14 client schedules on a fresh empty games table; existing installs retain their configuration.
3. Harden validation and authorization, enforce verified + published + source on every public path, remove automatic result seeding. CSV: ISO dates, bilingual/slug resolution, duplicate-safe inserts, bounded files/rows, draft-only import, formula-safe export, persistent counts/errors and review metadata. Admin forms use capabilities/nonces/PRG. Deactivate games instead of destructive deletion.
4. Retain legacy shortcode names and REST namespace with safe informational rendering; add bounded date/month/game archive filtering and pagination. Schedule occurrence calculation uses WordPress timezone and calendar dates, independently of display order.
5. Redesign presentation: navy/gold editorial identity, responsive cards and scrollable tables, keyboard navigation, real empty states. Native Customizer for branding/general settings and homepage per-section editing/ordering/visibility/images; native FAQ content and WordPress posts/pages. No betting/payment/prediction/promotional source copy or third-party contact details.
6. SEO: title-tag, canonical, descriptions/OG, WebSite schema, breadcrumbs, sitemap-compatible native pages, noindex filtered searches. Avoid duplicate metadata with common SEO plugins.
7. Research accessible reference charts. Deliver only a clearly labeled partial CSV with source names/URLs/check status and evidence; do not silently equate HR Satta with HR Matka or Dwarka with HUDA City. Do not auto-import on activation. Missing or conflicting values remain missing.
8. Test clean activation, additive upgrades/data retention, all schedule times, midnight, record review/public privacy, CSV validation/duplicates/export, REST/shortcodes, admin permissions, templates and responsive behavior. Record exact runtime and untested hosting constraints.
9. Package two installable ZIPs and deliver README, CHANGELOG, historical CSV, source notes and testing report. Verify archives and original hashes.

## Deliberate compatibility boundaries
Presentation, legacy countdown animation and ACF settings are not copied blindly. Existing database identifiers, unique keys, schedule rows and result values are preserved. New native theme settings do not overwrite ACF options; manual content migration is documented. Legacy unverified published records remain stored with their status but hidden publicly. Old shortcodes remain registered; countdown-oriented aliases become informational schedule components. No automatic wagering, payout, betting recommendations or synthetic history.
